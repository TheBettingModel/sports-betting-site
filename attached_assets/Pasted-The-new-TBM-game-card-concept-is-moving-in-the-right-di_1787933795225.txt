9. ADD TBM FAIR PRICE
==================================================

If a valid Model Win Probability exists, calculate/display the corresponding TBM fair odds.

Example:

Model Probability:

64.0%

TBM Fair American Odds:

approximately -178

Display:

-178
FAIR PRICE

This is a very useful professional betting metric because it shows what TBM believes the correct price should be.

IMPORTANT:

Use mathematically correct American odds conversion.

For probability > 50%:

Fair American Odds =
-(Probability / (1 - Probability)) × 100

For probability < 50%:

Fair American Odds =
((1 - Probability) / Probability) × 100

Round appropriately for display.

11. CRITICAL: AUDIT THE CURRENT "MODEL EDGE"
==================================================

Before changing the edge display, inspect exactly what the existing backend field means.

The current example shows:

MODEL WIN PROBABILITY
64.0%

MARKET IMPLIED
65.5%

MODEL EDGE
+14.6%

Those three numbers appear mathematically inconsistent if "Model Edge" is intended to represent probability edge.

64.0% - 65.5% = -1.5 percentage points.

It does NOT equal +14.6%.

Therefore:

DO NOT simply display these values together without understanding their definitions.

Audit:

- model_edge
- edge
- probability_edge
- expected_value
- market_edge
- pricing_edge
- value_edge

and determine exactly what each backend field represents.

12. DO NOT CONFUSE DIFFERENT TYPES OF EDGE
==================================================

There may be multiple legitimate edge calculations in TBM.

For example:

PROBABILITY EDGE

Model Win Probability
minus
Market Implied Probability

Example:

64.0% - 65.5% = -1.5 percentage points


EXPECTED VALUE / BETTING EDGE

This may use:

Model probability
Betting odds
Potential payout

and can produce a different number.


MODEL SCORE EDGE

The TBM backend may also have a proprietary model advantage score.

These are NOT interchangeable.

Do not label all of them:

MODEL EDGE

Determine what the +14.6% actually represents.

If it represents a proprietary TBM value metric, rename it something clear such as:

TBM VALUE EDGE

If it represents expected value:

EXPECTED VALUE

If it represents probability difference:

PROBABILITY EDGE

The UI must never imply mathematically incorrect relationships.

17. THREE LEVELS OF INFORMATION
==================================================

The TBM interface should intentionally have three layers.

LEVEL 1 — MODEL BOARD

Purpose:

"What should I bet?"

Show only:

- Matchup
- Pick
- Odds
- Recommendation
- Units
- Win probability
- Fair price
- Market price
- Primary value metric


LEVEL 2 — VIEW ANALYSIS

Purpose:

"Why does TBM like this bet?"

Show:

- Key matchup advantages
- Model factors
- Market information
- Pricing information
- Risk factors
- Sharp activity


LEVEL 3 — FULL MODEL DATA

Purpose:

"Show me everything."

This can contain:

- Full model scoring
- Historical inputs
- Market intelligence
- CLV
- Opening/current line
- Line movement
- Sharp books
- Line shopping
- Sport-specific analytics
- Injuries
- Weather
- Rest
- Pitchers
- Lineups
- Advanced efficiency metrics
- etc.

This architecture allows casual bettors and advanced bettors to use the same product.
