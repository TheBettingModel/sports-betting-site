# TASK #234 — TBM GUARDED SERVING RUNTIME + MODEL APPROVAL ADAPTER

## MISSION

Build the missing production-serving infrastructure identified by Task #233 so The Betting Model can safely perform a subsequent controlled cutover of MLB V4 and NCAAF Next-Gen.

Task #233 established that the primary blocker is NOT repository security, PIT integrity, or leakage.

The primary blocker is that the production application does not currently have the runtime machinery required to safely route, approve, identify, fall back from, and observe next-generation model predictions.

Task #234 must BUILD that machinery.

This is an IMPLEMENTATION TASK, not another documentation-only readiness audit.

The required outcome is:

1. MLB has a real configurable guarded-serving runtime.
2. NCAAF has a real configurable guarded-serving runtime.
3. Next-generation artifact approval is explicitly separated from serving mode.
4. Incumbent V1 engines remain unchanged and available.
5. Explicit fallback and PASS behavior exists.
6. Operational kill switches exist.
7. Every generated prediction truthfully identifies its model/engine/version.
8. Official next-generation predictions can be persisted immutably.
9. The API exposes runtime model identity.
10. The owner/admin surface exposes actual runtime model identity and health.
11. A real-slate guarded smoke-test path exists.
12. The system is technically capable of performing a subsequent production cutover without another serving-infrastructure rebuild.
13. No currently barred/unapproved model artifact is forced into public production merely to satisfy this task.

Task #234 is intended to build the runway for:

TASK #235 — PRODUCTION APPROVAL + LIVE CUTOVER

DO NOT prematurely claim MLB V4 or NCAAF Next-Gen is live unless it actually becomes approved and publicly served during this task.

The primary goal of #234 is to ensure that after completion, the remaining launch question is MODEL APPROVAL/CUTOVER — not missing production infrastructure.
